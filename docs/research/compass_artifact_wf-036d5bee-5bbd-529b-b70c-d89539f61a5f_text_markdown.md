# Project Sentinel — Deepened Reference Pass (2025–2026): New Repos, Competitors & Theory

## TL;DR
- **Yes, multiple teams have now built systems that overlap heavily with Project Sentinel** — the closest single open-source analog remains **aliasrobotics/cai** (~9,447★, MIT-for-research), which uniquely combines autonomous offense with self-hardening against prompt injection (arXiv:2508.21669); the closest commercial analogs launched in 2025–2026 are **RunSybil** ($40M, Mar 2026), **Tenzai** ($75M seed, Nov 2025), **Novee** ($51.5M), and **Xint Pulse**. No single project matches all 12 weeks, so Sentinel's integration of offense + Security-FOR-AI + LLMOps is still a differentiated capstone.
- This pass adds **~40 new, verified GitHub/GitLab references** not in the prior report, each with star/license/date where available, mapped to the 12 weeks and skills S1–S11, plus new academic/standards backing (A2A spec, OpenID "Identity Management for Agentic AI," CaMeL, LlamaFirewall, MITRE ATLAS v5.1/v5.4).
- Strongest new build/learn targets by phase: **DefectDojo** + GitLab Duo Agent Platform pattern (Phase 1); **HexStrike-AI / secops-mcp / mcp-security-hub** for MCP tool-wrapping and **Strix** for multi-agent orchestration (Phase 2); **Meta LlamaFirewall** + **CAI** four-layer guardrails + GitLab composite-identity/HITL pattern (Phase 3); **vLLM production-stack + KEDA/DCGM** + LLM-as-judge false-positive research (Phase 4).

## Key Findings

1. **The "combined offense + self-defense" niche Sentinel occupies is real but sparsely populated.** CAI is the one OSS framework explicitly doing both, and its own paper shows why it matters: AI hacking tools can themselves be hijacked by prompt injection. This validates Sentinel's Phase 3 as a genuine research contribution rather than a checkbox.
2. **MCP has become the de-facto integration substrate for AI-security tooling.** Since late 2024, adoption has exploded — Anthropic's Dec 9, 2025 ecosystem update reported "more than 10,000 active public MCP servers," and a May 24, 2026 GitHub Search API pull counted 15,926 repositories carrying the `mcp-server` topic (per digitalapplied.com's MCP Adoption Statistics 2026). The security-tool-wrapper pattern (HexStrike, secops-mcp, mcp-security-hub, cyproxio→Bolt) is now the standard way to give an agent access to nmap/nuclei/sqlmap/ffuf, directly matching Sentinel Weeks 2, 4–6.
3. **Agent IAM is the least-solved area industry-wide** — a genuine research frontier. Entro Security's "2025 State of Non-Human Identities and Secrets in Cybersecurity" report found **97% of non-human identities carry excessive privileges** (also cited by CSO Online, Nov 2025), while a CSA/Oasis Security survey (Aug–Sep 2025, 383 respondents) found 51% of organizations cited over-permissioned access as their top NHI pain point. OAuth 2.1/OIDC + MCP's RFC 9728 + A2A AgentCards + AGNTCY/SPIFFE are the emerging building blocks for Sentinel Week 2.
4. **Prompt-injection defense is provably unsolved.** Nasr et al. ("The Attacker Moves Second," arXiv:2510.09023, Oct 2025; joint OpenAI/Anthropic/Google DeepMind) bypassed 12 recent defenses "with attack success rate above 90% for most; importantly, the majority of defenses originally reported near-zero attack success rates." Sentinel Week 7 should therefore layer defenses (spotlighting + LlamaFirewall + CaMeL-style capability gating) and treat them as risk-reduction, not guarantees.
5. **LLM-as-judge evaluation (Week 10) has a specific, citable failure mode.** No prior security benchmark reported false-positive rates, and judges are themselves attackable — Zhao et al. (Tencent AI Lab, arXiv:2507.08794) show "master key" inputs (non-word symbols like ":" or reasoning openers like "Thought process:") elicit false-positive rates "as high as 80%" across judges including GPT-o1 and Claude-4. Sentinel's eval design should explicitly measure FP rate and harden the judge.
6. **The production/GPU-FinOps stack (Week 11) has consolidated** on vLLM + KEDA (queue-depth trigger `vllm:num_requests_waiting`) + DCGM exporter + cost-per-token recording rule. This is well-documented and low-risk to implement.

## Details (organized by Phase/Week, "NEW this pass" flagged)

### PHASE 1 — Infrastructure & Cyber Baseline

**Week 1 — SAST/DAST CI/CD + unified vulnerability data lake**
- **NEW — DefectDojo (DefectDojo/django-DefectDojo)**: OWASP flagship, BSD-3-Clause, Python; parses 200+ scanners (Semgrep, Bandit, CodeQL, ZAP, Burp, Trivy, Checkov) into one model; intelligent deduplication (CWE + file path + endpoint + hash), typically collapsing ~500 findings from 5 tools to ~150 unique. Latest release in the v2.55.x series (Feb 2026). The single best fit for the "unified vulnerability data lake" — the dedup mechanism and parser breadth are the new, citable detail.
- **NEW — Dependency-Track** (SBOM/SCA continuous monitoring) and **Faraday** (open-source vuln management, 80+ integrations, pentest-oriented) as complementary aggregators.
- **NEW — GitLab 18.10+ "AI-native triage"**: GitLab Duo Agent Platform uses an LLM for agentic reasoning to score whether a SAST finding is a false positive, and (beta) auto-opens a merge request with a proposed fix. A direct, documented production reference for wiring LLM triage on top of a vuln lake.
- Core scanners to standardize on (community-award consensus): **Semgrep** (SAST), **OWASP ZAP** + **Nikto** (DAST), **Trivy** (containers), **TruffleHog** (secrets), **Nmap** (network).

**Week 2 — API Gateway + Agent IAM (MCP/A2A, scoped per-agent permissions)**
- **NEW — a2aproject/A2A official spec** (a2a-protocol.org): A2A is now donated to the Linux Foundation; security model = TLS transport, identity handled at HTTP layer (not in JSON-RPC payload), AgentCard declares OAuth2/OIDC/API-key/mTLS schemes. Critical accuracy point: A2A was "made with communication, not security, in mind" — credential provisioning and trust establishment are explicitly out of scope, so Sentinel must add its own authz layer.
- **NEW — agntcy/identity** (Apache-2.0, Go/Python, v0.0.23 Jan 2026, ~95★) + **agntcy/identity-service** + **agntcy/identity-spec**: reference implementation of verifiable agent identity — BYO-ID from Okta/A2A AgentCards/W3C DIDs, "Agent Badges" carrying Verifiable Credentials, Issuer CLI, works with MCP servers and multi-agent systems. Prior report cited AGNTCY generically; these are the specific, installable repos with an Okta-based quickstart.
- **NEW — OpenID Foundation "Identity Management for Agentic AI" (Oct 2025)**: authoritative position that OAuth 2.1/OIDC already cover many agent cases within bounded scopes but three gaps remain (agent-vs-user mode tracking, fragmented proprietary systems, delegation). Pair with **SPIFFE/SPIRE** (cryptographic workload identity via mTLS, HashiCorp 2025 guidance) for large agent populations.
- **NEW — MCP spec 2025-11-05 mandates OAuth 2.1** for remote servers, using RFC 9728 Protected Resource Metadata (401 → discovery) and PKCE authorization-code flow for act-on-behalf-of-user delegation. The concrete standard for Sentinel's "strictly scoped per-agent permissions."
- **NEW — IETF drafts (2026)**: `draft-klrc-aiagent-auth` (AI agent auth/authz), OAuth "transaction tokens for agents," and the AIP "Agent Identity Protocol for Verifiable Delegation across MCP and A2A" (arXiv:2603.24775) — cutting-edge, useful to cite as direction of travel.
- Gateways: **Kong/Tyk** (prior report) remain valid; add **Pomerium** (identity-aware proxy with native MCP support) and enterprise "AI bastion/AI-gateway" patterns (RBAC, audit, rate-limit, cost tracking) seen in the mcp-security topic.

**Week 3 — Threat-Intel RAG (Hybrid Search + GraphRAG over CVE/OWASP/pentest reports)**
- **NEW — CTINexus dataset** (Cheng et al., arXiv:2410.21060): 150 real CTI reports, 26 entity types, 855 relationship types — a ready-made evaluation corpus for a cyber-CTI knowledge graph.
- **NEW — "ATT&CK to CVE" KG** (Rahman et al., GTA3 '25 / Nov 2025): Neo4j KG linking CVE→CWE→CAPEC→ATT&CK with CVSS/CPE properties; directly models the CVE-to-mitigation traversal Sentinel's RAG needs.
- **NEW — CTI-Thinker** (Springer *Cybersecurity*, 2025) and **CTIKG** (COLM 2024) for LLM-driven CTI-KG construction; **SEPSES** and **CyberGraph** as earlier integrated CVE/CWE/CAPEC KGs.
- **NEW — "Beyond RAG for Cyber Threat Intelligence"** (arXiv:2604.11419): systematic comparison of vanilla RAG vs GraphRAG vs agentic retrieval on CTI — essential reading to justify Sentinel's hybrid + GraphRAG choice, and it flags that GraphRAG's relational structure creates a new poisoning attack surface (ties into Phase 3).
- Prior report's Microsoft GraphRAG and CVE-KGRAG remain core tooling; pgvector (as PentAGI uses) is the pragmatic vector store.

### PHASE 3 — Security FOR AI (hardening the agentic system)

**Week 7 — Indirect prompt-injection defense + guardrails**
- **NEW — Meta LlamaFirewall (meta-llama/PurpleLlama, ~4,254★, code MIT / models under Llama Community License)**: the most complete OSS guardrail stack — **PromptGuard 2** (BERT-style jailbreak detector, always-on), **AlignmentCheck** (chain-of-thought auditor for goal hijacking/indirect injection), **CodeShield** (Semgrep+regex static analysis, 8 languages, 96% precision/79% recall on CyberSecEval3). On AgentDojo it cut attack success 17.6%→1.7%. Recommended primary guardrail for Sentinel; integrates with LangChain.
- **NEW — CaMeL "Defeating Prompt Injections by Design"** (Debenedetti et al., Google DeepMind/ETH, arXiv:2503.18813): capability-based dual-LLM (Privileged + Quarantined) with data-provenance tainting; 0 successful attacks on AgentDojo default vs 8 for next-best defense. The architectural gold standard to cite for Sentinel's design; pair with Microsoft **Spotlighting** (arXiv:2403.14720, delimiting/datamarking/encoding) as cheap baseline hygiene.
- **NEW — critical honesty caveat**: "The Attacker Moves Second" (Nasr et al., arXiv:2510.09023) bypassed 12 published defenses at >90% ASR for most (>90% vs ProtectAI, PromptGuard, Model Armor; 71% vs PIGuard), and "the majority of defenses originally reported near-zero attack success rates." Sentinel must frame guardrails as probabilistic risk-reduction. Anthropic separately reports Claude Opus 4.5 browser agent reduced to ~1% ASR via RL — a vendor claim, not independently verified.
- **NEW — nyit-vancouver/mcp-security** + **slowmist/MCP-Security-Checklist** + **Puliczek/awesome-mcp-security**: a deliberately-malicious tool-poisoning MCP server (JCP 2026 paper, DOI 10.3390/jcp6030084), a 57-threat STRIDE/DREAD checklist, and a curated MCP-security list — ideal for building Sentinel's "deliberately vulnerable staging app" that returns malicious payloads.
- **NEW — CAI (aliasrobotics/cai, ~9,447★, MIT-for-research)** + paper **arXiv:2508.21669 "Cybersecurity AI: Hacking the AI Hackers via Prompt Injection"** (Mayoral-Vilches & Rynning, submitted 29 Aug 2025; v2 15 Nov 2025): demonstrates PoC prompt-injection exploits against CAI's own framework/CLI (analogized to XSS — malicious text hidden in trusted content that hijacks agent execution), then details a multi-layered self-hardening implementation; concludes prompt injection is a recurring, systemic issue in LLM architectures requiring dedicated ongoing work. CAI's site advertises a "four-layer guardrail security system." The single most on-point precedent for Sentinel's whole Phase 3 thesis.
- Prior report's NeMo Guardrails, NVIDIA Garak, protectai/llm-guard, Rebuff remain valid; add **DeepTeam** (Confident AI, 40+ vuln types), **Promptfoo** (30,000+ devs, CI/CD red-teaming), and **HiddenLayer** (used by GitLab Duo for prompt-injection detection).
- Vulnerable staging targets: prior report's OWASP Juice Shop/DVWA/WebGoat remain the standard.

**Week 8 — HITL approval gates for high-risk actions**
- **NEW — GitLab Duo tool-level approval policies (GitLab 19.1)**: production-grade, directly-citable pattern — each tool mapped to Allow / Ask / Deny; "Ask" shows an inline approval card before execution and emits an audit event for every decision. **Week 9 — Real-time PII redaction from agent memory/logs/RAG**

## Recommendations
1. **Anchor the build on three OSS reference architectures**: Strix (multi-agent offense topology, Week 6), CAI (offense+self-hardening, Phase 3 thesis), and DefectDojo (vuln lake, Week 1). Clone and study these first; they collectively cover the most Sentinel surface area.
2. **For Agent IAM (Week 2), adopt standards not bespoke auth**: MCP OAuth 2.1 + RFC 9728 for tool access, AGNTCY/identity for verifiable agent badges, and document the A2A "security-out-of-scope" gap as a deliberate design decision. Benchmark: every agent must fail-closed when presenting an out-of-scope token.
3. **For Week 7, layer three guardrails and measure ASR**: Spotlighting (cheap, always-on) → LlamaFirewall PromptGuard2/AlignmentCheck → CaMeL-style capability gating for state-changing tools. Threshold to change approach: if adaptive-attack ASR on your staging app exceeds ~10%, escalate to CaMeL-style provenance tainting rather than adding more heuristics.
4. **For Week 10, make false-positive rate the headline metric** (nobody else reports it) and harden the judge against "master-key" attacks via structured rubrics + evidence spans + multi-pass aggregation (CIPHER pattern).
5. **For Week 11, copy the vLLM+KEDA queue-depth recipe verbatim** and add a cost-per-token recording rule on day one; set `minReplicaCount: 1`, `cooldownPeriod: 300`.
6. **For Week 12, use the 2025–2026 funding/pricing data** (Xint $3k/scan, RunSybil $40M, Tenzai $75M) as the market-validation and ROI-anchor section; explicitly position Sentinel's differentiator as the integrated Security-FOR-AI layer that pure-offense competitors lack.
7. **Maintain the ethical framing throughout**: every new offensive repo cited (Strix, hexstrike-ai, CAI, xalgorix) carries an explicit "authorized-testing-only" disclaimer; mirror this in Sentinel's PRD, keep HITL gates on all state-changing actions, and test only the team's own staging replica.

## Caveats
- **Star counts fluctuate daily**; figures are "as of ~July 15–16, 2026" from GitHub pages/API. DefectDojo's exact star count was not verified this pass (BSD-3 license and active maintenance confirmed) — re-check before publishing a number.
- **License nuance**: PurpleLlama/LlamaFirewall code is permissive (MIT for evals) but bundled models use the custom Llama Community License; CAI is "MIT for research," commercial use needs a separate license; Armur-Ai/Pentest-Swarm-AI is AGPL-3.0 (copyleft — relevant if Sentinel reuses code). Verify license compatibility before incorporating any code.
- **Vendor vs verified claims**: XBOW's #1 HackerOne rank, PentestGPT's 86.5%, Xint/RunSybil/Tenzai capability and funding figures, and Anthropic's ~1% ASR are self-reported or press-release figures, not independently reproduced. Benchmark numbers (ARTEMIS 9-vs-49, AXE 30% on CVE-Bench) come from academic papers and are more reliable.
- **MCP-server counts**: the "13,000+" figure sometimes cited is not traceable to a single primary source; prefer Anthropic's "10,000+ active public MCP servers" (Dec 9, 2025) or the GitHub-topic count of 15,926 repos (May 24, 2026), and cite the source with each.
- **Prompt-injection defenses are not solved**; treat all Week 7 controls as probabilistic. The presence of a guardrail is not enforcement — the microsoft/agent-governance-toolkit analysis found detection modules often not wired into the enforcement lifecycle.
- Some cited sources are secondary aggregators/curated lists (awesome-ai-pentest, LLM4Pentest, blog posts); the primary sources (official repos, arXiv papers, official specs) have been prioritized where possible and should be the citation of record.
